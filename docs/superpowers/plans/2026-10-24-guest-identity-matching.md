# Guest Identity Matching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop `/join` from creating a disconnected `GuestAttendee` for someone who already has a
sign-in account or an event team record, which today shows up as a duplicate row on
`/admin/attendance`.

**Architecture:** One new service (`GuestIdentityMatchService`) is the single source of truth for
the matching rule. It's called from the live `/account/join` handler (block sign-in-capable people,
link team members to their `EventStaff` row) and from a one-time `SeedService` startup repair that
backfills existing unlinked visits. `AttendanceService.GetRosterAsync` is updated to use the new link
to collapse a linked guest and their team row into one entry.

**Tech Stack:** .NET 8 / EF Core 8 / PostgreSQL (Npgsql), Blazor Server + minimal APIs.

**Spec:** `docs/superpowers/specs/2026-10-24-guest-identity-matching-design.md`

## Global Constraints

- **No automated test suite exists in this repo** (`CLAUDE.md`: "There's no automated test suite, so
  PRs carry a manual checklist"). This plan does **not** introduce one — every task's verification
  step is a manual check (`dotnet build`, local run, direct SQL against the local `hbda_dev` DB, or
  the browser), matching how every other feature in this codebase has shipped.
- Match precision is exact-match-after-normalization only (reuse `GuestAccessService.Normalize`) —
  no fuzzy/nickname matching.
- Case 1 (sign-in match) is a hard block — no "continue as guest anyway" escape hatch.
- Case 2 (team match) grants **no elevated access** — the guest cookie/session is identical to any
  other guest; only the Attendance roster's display changes.
- Ambiguous team matches (more than one `CanSignIn = false` `EventStaff` row with the same
  normalized name on one event) fall back silently to a plain, unlinked guest — no logging, no admin
  review UI.
- `dotnet build` must show no new warnings beyond the existing baseline of 3
  (`Dashboard.razor` CS0414, `Announcements.razor` CS4014, `MainLayout.razor` CS0618).

```csharp
using CampClotNot.Data;
using Microsoft.EntityFrameworkCore;

namespace CampClotNot.Services;

public enum GuestIdentityMatch
{
    NoMatch,
    SignInRequired,
    LinkedTeamMember
}

public record GuestIdentityMatchResult(GuestIdentityMatch Kind, Guid? TeamEventStaffId = null)
{
    public static readonly GuestIdentityMatchResult None = new(GuestIdentityMatch.NoMatch);
    public static readonly GuestIdentityMatchResult SignIn = new(GuestIdentityMatch.SignInRequired);
    public static GuestIdentityMatchResult Team(Guid eventStaffId) =>
        new(GuestIdentityMatch.LinkedTeamMember, eventStaffId);
}

/// <summary>
/// Matches a typed guest name against this event's team roster first, then — only if nothing there
/// matches — against every sign-in-capable account site-wide. See
/// docs/superpowers/specs/2026-10-24-guest-identity-matching-design.md for the full rule.
/// </summary>
public class GuestIdentityMatchService(IDbContextFactory<AppDbContext> factory)
{
    public async Task<GuestIdentityMatchResult> MatchAsync(string firstName, string lastName, Guid eventId)
    {
        var normFirst = GuestAccessService.Normalize(firstName);
        var normLast = GuestAccessService.Normalize(lastName);

        using var db = factory.CreateDbContext();

        var team = await db.EventStaff
            .Where(s => s.EventId == eventId)
            .Include(s => s.User)
            .ToListAsync();
        var teamMatches = team
            .Where(s => GuestAccessService.Normalize(s.User.FirstName) == normFirst
                     && GuestAccessService.Normalize(s.User.LastName) == normLast)
            .ToList();

        if (teamMatches.Count > 0)
        {
            if (teamMatches.Any(s => s.User.CanSignIn)) return GuestIdentityMatchResult.SignIn;
            // All matches are CanSignIn=false. Exactly one -> link it. More than one -> ambiguous,
            // don't guess which one they mean.
            return teamMatches.Count == 1
                ? GuestIdentityMatchResult.Team(teamMatches[0].EventStaffId)
                : GuestIdentityMatchResult.None;
        }

        var accounts = await db.Users
            .Where(u => u.CanSignIn)
            .Select(u => new { u.FirstName, u.LastName })
            .ToListAsync();
        var hasAccount = accounts.Any(u =>
            GuestAccessService.Normalize(u.FirstName) == normFirst &&
            GuestAccessService.Normalize(u.LastName) == normLast);

        return hasAccount ? GuestIdentityMatchResult.SignIn : GuestIdentityMatchResult.None;
    }
}
```

```csharp
    /// <summary>
    /// Tags an existing guest visit with the team record it matched at join time (#354), so
    /// Attendance shows one row with their role instead of a separate "Guest" duplicate. A no-op if
    /// the visit doesn't exist yet or is already linked.
    /// </summary>
    public async Task LinkVisitToTeamAsync(Guid guestAttendeeId, Guid eventId, Guid eventStaffId)
    {
        using var db = factory.CreateDbContext();
        var visit = await db.GuestEventVisits.FirstOrDefaultAsync(v =>
            v.GuestAttendeeId == guestAttendeeId && v.EventId == eventId);
        if (visit is null || visit.LinkedEventStaffId.HasValue) return;
        visit.LinkedEventStaffId = eventStaffId;
        await db.SaveChangesAsync();
    }
```

Add this new private method anywhere alongside the other repair methods (e.g. right after

```csharp
    /// <summary>
    /// One-time repair for guest visits created before #354: matches each still-unlinked visit
    /// against its event's team roster and links it when exactly one CanSignIn=false record
    /// matches by name. Leaves ambiguous or sign-in-account matches alone — same rule as the live
    /// /join check (GuestIdentityMatchService), just applied retroactively.
    /// </summary>
    private async Task BackfillGuestTeamLinksAsync(AppDbContext db)
    {
        var unlinked = await db.GuestEventVisits
            .Where(v => v.LinkedEventStaffId == null)
            .Include(v => v.GuestAttendee)
            .ToListAsync();
        if (unlinked.Count == 0) return;

        var linked = 0;
        foreach (var visit in unlinked)
        {
            var match = await identityMatch.MatchAsync(
                visit.GuestAttendee.FirstName, visit.GuestAttendee.LastName, visit.EventId);
            if (match.Kind == GuestIdentityMatch.LinkedTeamMember)
            {
                visit.LinkedEventStaffId = match.TeamEventStaffId;
                linked++;
            }
        }
        if (linked > 0)
        {
            await db.SaveChangesAsync();
            logger.LogInformation("Linked {Count} existing guest visit(s) to a team record.", linked);
        }
    }
```
